# Scoped Subgraphs

Scoped subgraphs are [[concepts/network-graph|network graph]] structures generated by the Cortex-side [[concepts/coverage-testing|network graph job]] as part of the security infrastructure pipeline. These subgraphs are derived from a larger [[concepts/list-graph-jobs|stakeholder graph view]] and are constrained to specific scopes relevant to particular security or organizational contexts. The generation process includes [[concepts/input-validation|input validation]] through the [[concepts/queue-graph-view|stakeholder_graph_view]] module to ensure [[concepts/data-conceptsintegrityintegrity|data integrity]] before processing.

## Graph Processing and Scoring

Once a scoped subgraph is generated, the system performs node and edge scoring operations to assign relevance or risk metrics to entities within the graph. These scored graphs are then stored as snapshots in the stakeholder_signal_store, creating a persistent record of the graph state at specific points in time. This snapshot mechanism enables temporal analysis and comparison of network structures.

## Signal Emission

The processing pipeline emits two primary signal types from scored subgraphs: warm-intro signals, which indicate validated introductions or connections within the network, and shared-al signals, which denote shared attributes or alignments between nodes. These signals are downstream artifacts used by other security and infrastructure systems to make decisions about access, trust, or organizational [[concepts/relationships|relationships]].
