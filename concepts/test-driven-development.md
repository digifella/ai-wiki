# Test-Driven Development

Test-Driven Development (TDD) is a [[concepts/coding|software development]] methodology where tests are written before implementation code, driving the design and ensuring [[concepts/accuracy|correctness]] through a rapid [[concepts/feedback|feedback]] cycle.

**Core Workflow:**
- Write a failing test (red)
- Implement minimal code to pass the test (green)
- Refactor while maintaining passing tests

**Modern Application: TDD with [[concepts/agentic-ai|AI Agents]]**
Integrating tests directly into the [[concepts/code|codebase]] and enabling [[concepts/agentic-ai|AI agents]] (like [[entities/claude-code|Claude Code]]) to execute them provides:
* **[[concepts/automated-feedback-loop|Automated feedback loop]]** for [[concepts/ai-generated-code|AI-generated code]]
* Continuous validation of correctness during development
* Reduced need for manual testing iterations
* **Core workflow for [[concepts/ai-coding|AI coding]] agents**: Leveraging TDD to [[concepts/ambition|drive]] agent-led implementation and [[concepts/verification|verification]]

**Key Benefits:**
- Prevents over-[[entities/national-academies|engineering]] through minimal implementation
- Creates safety net for refactoring
- Documents requirements through executable tests
