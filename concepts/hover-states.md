# Hover States

Hover states are visual changes that occur when a user positions their [[concepts/cursor|cursor]] over an interactive UI element. They serve as a critical [[concepts/feedback|feedback]] mechanism, signaling to users that an element is clickable or interactive. By providing immediate visual response, hover states help users understand what actions are available and reduce uncertainty about which interface elements they can interact with. This feedback is particularly important in web and desktop interfaces where cursor position is a primary input method.

## Common Visual Treatments

Hover state effects take many forms depending on the design system and context. Common treatments include color shifts, such as darkening a button background or changing link text color, to indicate activity. Other frequent modifications involve subtle [[concepts/computational-scaling|scaling]], adding drop [[concepts/shadows|shadows]], or underlining text to mimic the physical sensation of pressing down or lifting an object. These changes are typically brief and reversible, disappearing immediately when the cursor moves away.

## Accessibility and Limitations

While effective for mouse-driven interfaces, hover states have significant limitations on touch devices where a cursor does not exist. Relying solely on hover for critical information or functionality can exclude users of [[concepts/portable-devices|mobile devices]] and those with motor impairments. Consequently, modern [[concepts/user-experience-design|UX design]] often pairs hover cues with other [[concepts/indicators|indicators]], such as focus states for keyboard navigation or persistent labels, to ensure the interface remains usable across different input methods and [[concepts/accessibility|accessibility]] requirements.
