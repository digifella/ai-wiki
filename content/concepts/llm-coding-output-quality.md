# LLM Coding Output Quality

## Definition
The measurable fidelity, correctness, efficiency, and maintainability of [[concepts/code|code]] generated by [[concepts/large-language-model]]s. High quality is defined by reduced [[concepts/data-hallucination|hallucination]] rates, adherence to architectural constraints, and minimal post-generation refactoring requirements.

## Optimization Strategies

### System Prompts & Context Management
*   **Structured [[concepts/instructions|Instructions]]**: Utilize explicit [[concepts/system-prompts|system prompts]] to define persona, constraints, and [[concepts/output|output]] formats.
*   **[[concepts/context-window|Context Window]] Management**: Prioritize relevant documentation and [[concepts/software|code]] snippets to prevent noise dilution.

### Specific Implementations & Case Studies
*   **[[entities/andre-karpathy|Karpathy]]'s [[concepts/claude-ai|Claude]].md Pattern**:
    *   [[concepts/adoption|Implementation]] of a dedicated `claude.md` (or equivalent context file) to inject high-fidelity project-specific guidelines directly into the LLM's system context.
    *   Reported significant improvements (10x metric cited) in output relevance and reduced iterative correction cycles.
    *   Detailed in: [[lab-notes/2026-05-23-Optimizing-LLM-Coding-Output-Quality-with-Karpathys-Clau|Optimizing LLM Coding Output Quality with Karpathy's Claude.md File]]

### Evaluation Metrics
*   **Pass@k**: Probability that [[concepts/assistive-technology|at]] least one of k sampled completions passes all tests.
*   **Human Evaluation**: Subjective assessment of code readability and idiomatic [[concepts/style|style]].
